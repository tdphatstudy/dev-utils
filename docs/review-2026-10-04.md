# Review DevUtils — 2026-10-04

## Kết luận

Ý tưởng phù hợp Electron: toolbox desktop local-first, các tool tải lazy, kho
mã hóa dùng chung với Keep. Tách main/preload/renderer/shared đã có nền tảng tốt.
**Chưa nên coi là sẵn sàng phát hành cho cả ba OS**: có lỗi parser Unix và các
luồng có thể làm mất khả năng mở dữ liệu vault. Ưu tiên sửa bảo toàn dữ liệu trước,
sau đó platform adapter và IPC; chưa cần đổi framework.

Review working tree gồm thay đổi chưa commit. Không sửa logic ứng dụng trong lần
review này. Đây là kiểm tra kiến trúc và các đường nhạy cảm, không phải audit toàn
bộ crypto, dependency vulnerability scan hay chứng nhận production.

## Findings có vị trí và cách xử lý

P1 = cần sửa trước release vì dữ liệu/bảo mật/tính năng chính; P2 = lỗi chức năng

### 1. [P1] Cache hardware key ghi đè secret cần để mở vault legacy

Vị trí: `src/main/secret-box/device-secret.ts:68`, `:125–129`;
`src/main/secret-box/vault.ts:489`.

`resolveDeviceKeyAForSetup()` gọi `cacheDeviceSecretHint()`; helper này ghi thẳng
vào cùng `privatebox-device.secret` từng chứa random key A của vault cũ. Tạo default
box hoặc setup một box mới có thể thay secret legacy bằng hardware key. Vault cũ
vẫn mã hóa bằng key A cũ sẽ không mở được nếu không có bản sao secret. Cache chạy
fire-and-forget còn khiến write race khó quan sát.

Sửa: tách cache hardware và legacy recovery material; tuyệt đối không overwrite
secret cũ chưa migrate. Migration phải chứng minh đọc được tất cả dữ liệu liên
quan, có backup và rollback. Test tạo box mới khi đang có legacy secret/vault.

### 2. [P1] Metadata lỗi bị xem là chưa tồn tại và tái tạo với salt mới

Vị trí: `src/main/secret-box/vault.ts:116–122`, `:486–509`.

`readVaultConfig()` trả `null` cho mọi lỗi đọc/parse. `ensureDefaultSecretBox()`
thấy `null` sẽ tạo config với salt mới và ghi vào đường dẫn cũ, kể cả khi đã có
`.putl`. Nếu metadata cũ hỏng tạm thời hoặc JSON bị truncate, việc tái tạo mất salt
cần để derive key giải mã tài liệu cũ; code không phục hồi từ `vault.json.bak`.

Sửa: phân biệt ENOENT với corrupt/unreadable/unsupported; fail closed nếu có dấu
vết vault; không tái tạo config trên kho đã có dữ liệu. Đưa ra recovery từ backup
có validation. Test corrupt JSON và lỗi đọc trong thư mục đã chứa tài liệu.

### 3. [P1] Rewrite SSH config đổi thứ tự ưu tiên của Host

Vị trí: `src/main/ssh/parse-config.ts:81–144`, gọi từ `src/main/ssh/crud.ts`.

Hàm gom `Host *` vào phần đầu và append host cụ thể xuống cuối. Với input:

```text
Host prod
  User deploy
Host *
  User fallback
```

Repro thực thi chính hàm parser/rewriter trả:

```text
Host *
  User fallback

Host prod
  User deploy
```

OpenSSH dùng giá trị đầu tiên cho phần lớn directive, nên user của `prod` đổi từ
`deploy` thành `fallback`. Một thao tác thêm/xóa host cũng có thể làm đổi host
không liên quan. Parser còn thu gọn directive lặp vào object và không mô hình hóa
ranh giới `Match`; không phù hợp để round-trip toàn bộ file.

Sửa: edit block tại vị trí gốc bằng representation giữ nguyên text/order; bảo toàn
syntax không hỗ trợ hoặc từ chối edit. Test thứ tự wildcard, nhiều IdentityFile,
Match/Include, comment và alias nhiều pattern. Quy tắc ưu tiên được mô tả trong
[OpenSSH ssh_config](https://man.openbsd.org/ssh_config).

### 4. [P1] Port Manager không parse được output Unix thông dụng

Vị trí: `src/main/platform/ports/unix.ts:13–15`, `:34`, `:54`.

`parseLsof()` lấy cột NAME từ index 8 nhưng regex lại yêu cầu prefix `TCP` ở NAME;
`TCP` đã nằm trong cột NODE. `parseSs()` ưu tiên index 4 (peer) thay vì index 3
(local) của output `ss -ltnH -p`. Lsof parse ra rỗng vẫn được coi là thành công nên
không thử fallback.

Repro với hai fixture:

```text
COMMAND PID USER FD TYPE DEVICE SIZE/OFF NODE NAME
node 123 alice 20u IPv4 12345 0t0 TCP *:3000 (LISTEN)

LISTEN 0 511 127.0.0.1:3000 0.0.0.0:* users:(("node",pid=123,fd=20))
```

Cả hai parser trả `[]`, thay vì port 3000/PID 123. macOS/Linux có thể thấy danh
sách rỗng dù đang có listener. Đây là repro bằng fixture, chưa chạy trên OS thật.

Sửa: parse format đúng hoặc dùng output machine-readable; thêm fixture macOS,
Linux, IPv6, missing permissions và tên process có khoảng trắng. Phân biệt
"không có listener" với "output chưa parse được".

### 5. [P1] API xóa nhận đường dẫn rỗng có thể xóa toàn bộ vault

Vị trí: `src/main/secret-box/fs-ops.ts:266–269`;
`src/main/secret-box/vault-paths.ts:5–15`.

`normalizeRelative('')` thành `''`, `resolveVaultPath('')` trả vault root.
`removeEntry('')` tiếp tục `rm(root, { recursive: true, force: true })`, gồm cả
metadata. Các alias như `.` cũng normalize về root. UI bình thường có thể không
gửi payload này, nhưng main API không bảo vệ dữ liệu trước input lỗi.

Sửa: validation riêng cho thao tác mutate: từ chối root, metadata `.privatebox`
và đường dẫn không thuộc entry được phép. Test bằng filesystem tạm, không vault
thật. Chưa thực thi thao tác xóa trong review.

### 6. [P1] Kiểm tra đường dẫn vault chưa chặn symlink/junction thoát root

Vị trí: `src/main/secret-box/vault-paths.ts:5–15`;
`src/main/secret-box/fs-ops.ts:182–183`, `:215–216`.

Resolver chỉ kiểm tra chuỗi path sau `resolve/relative`, không kiểm tra realpath
hay parent chứa symlink. Nếu trong vault có link `linked` trỏ ra ngoài, tạo file
hoặc mkdir dưới `linked/...` sẽ thao tác ngoài vault dù chuỗi path vẫn nằm trong
root. Điều kiện là có link/junction tồn tại trên disk; không cần UI liệt kê nó.

Sửa: reject symlink/junction trong đường đi hoặc validate canonical existing
parents và root; thiết kế chống thay đổi link giữa validation và IO. Test link
ngoài root trên OS hỗ trợ; báo rõ khi test Windows thiếu quyền tạo link.

### 7. [P2] Hardware fingerprint không đảm bảo mở lại sau cài OS

Vị trí: `src/main/secret-box/machine-id.ts:88–98`, `:118–131`.

Linux gộp cả `/etc/machine-id` vào hardware parts, rồi hash toàn bộ tập. Nếu cài
lại OS đổi machine-id hoặc quyền đọc DMI đổi, key A cũng đổi dù máy vật lý giữ
nguyên. Khi cache userData cũ không còn, device vault không mở được bằng mật khẩu
B. Đây là failure mode suy ra trực tiếp từ key derivation, chưa mô phỏng reinstall.
Windows cũng chỉ dùng `wmic`; cần kiểm tra khả năng có lệnh này trên các bản OS
đích, không mặc định mọi máy đều có.

Sửa: version hóa nguồn identity, thiết kế recovery/portable export và lưu thông
tin tương thích cần thiết. Đừng thay thuật toán derive cho kho cũ một cách silent.
Fingerprint là ID, không nên mô tả nó như một secret độc lập có entropy cao.

### 8. [P2] CSP chặn audio/video blob được MediaViewer tạo ra

Vị trí: `src/renderer/index.html:7`,
`src/renderer/src/features/privatebox/editors/MediaViewer.tsx:83`, `:96`.

Viewer tạo `blob:` URL nhưng CSP không có `media-src`; directive fallback về
`default-src 'self'`, không cho phép blob media. `img-src` đã có blob nhưng không
áp dụng cho audio/video. Playback bị chặn bất kể codec đã được hỗ trợ.

Sửa: thêm policy media hẹp, ví dụ `media-src 'self' blob:`, rồi kiểm tra playback
trong app đóng gói. Đánh giá codec/MIME riêng, không mở mọi scheme. Theo
[CSP media-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/media-src),
directive này fallback về default-src nếu vắng mặt. Chưa smoke-test media qua UI.

### 9. [P2] History "on unmount" lại ghi trên mỗi lần input đổi

Vị trí: `src/renderer/src/hooks/useToolDraft.ts:34–45`;
`src/renderer/src/features/tools/json/JsonStudio.tsx:26`.

Effect phụ thuộc `value`; React chạy cleanup trước khi effect chạy lại với value
mới. Cleanup push history nên lịch sử nhận nhiều phiên bản trong lúc gõ, có thể
chiếm hết giới hạn 40 entries thay vì chỉ snapshot khi rời tool. Draft timer cũng
bị hủy khi unmount nên input cuối trong 400 ms có thể chưa được lưu.

Sửa: ref giữ giá trị mới nhất, cleanup chỉ theo vòng đời/tool identity, flush
draft cuối khi rời tool nếu privacy policy cho phép. Test typing + navigation
và StrictMode. Chưa chạy renderer integration test.

## Các điểm cần harden thêm

- Main bật sandbox/contextIsolation/webSecurity đúng, nhưng chưa thấy guard
  `will-navigate`, allowlist scheme cho `shell.openExternal(details.url)` hay
  validation sender chung cho IPC. Payload nhiều handler mới có TS type. Cần
  kiểm tra thêm đường đưa URL untrusted vào UI để đánh giá exploit thực tế; không
  coi thiếu guard tự nó là một exploit đã chứng minh. Đối chiếu
  [Electron security](https://www.electronjs.org/docs/latest/tutorial/security).
- `file:hash` đọc toàn file và HTTP nhận toàn response vào RAM; cần stream và
  giới hạn dung lượng. Crypto sync chạy tại main có thể block UI khi input nặng.
- `NO_HISTORY_TOOLS` chưa chứa `security.keygen`, `network.ssh`, `privatebox.keep`.
  Chưa thấy KeygenTool dùng useToolDraft nên **chưa có bằng chứng key đang rò vào
  history**; thiết kế metadata privacy theo tool sẽ tránh lỗi khi mở rộng.
- Private key ghi bằng writeFile trước khi chmod, chưa có transaction cho cặp
  public/private; rename key chưa cập nhật IdentityFile. Cần chốt hành vi sản phẩm
  và test failure giữa hai bước, quyền Unix/ACL Windows.
- Chưa có CI matrix trong snapshot ban đầu, test UI/Electron hay quy trình ký
  đầy đủ. Build có vendor SQL khoảng 2.9 MB, vượt ngưỡng warning 900 kB; chunk
  lazy giúp startup nhưng cần đo thời gian mở SQL Studio thực tế.
